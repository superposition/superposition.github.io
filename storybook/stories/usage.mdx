# When to use what

Pick the component by the job you are doing, not by the look. Everything below draws with the tokens in `assets/tokens.css`, and the workbench imports the site's own stylesheets, so what you see here is what ships.

## Button

Use a button for an action: submit, follow, copy, toggle. If it goes somewhere, use a link. If it reads inside a sentence, use the text variant.

**Primary** is the one action on a view. If two sit side by side, neither is primary. **Secondary** is the alternative beside it. **Ghost** is for rows and chrome, where a filled box is too loud — it has no boundary at rest, so check it on a photograph as well as on the ground. **Text** is an action that reads as a link, inside a sentence or a row of them.

Sizes are `btn-sm` for dense rows and `btn-lg` for the one action on a page; `btn-block` fills its container. Hover, focus, active and disabled are live states, not classes you apply — tab to a button and look at it before you call it done.

## Link

Use a link to go somewhere, and let the form say where it is: a **chrome link** for the nav and footers, a **prose link** inside an article, and the bare `a` when nothing else owns the line.

The two colours are not decoration. A link in the chrome and a link inside a piece of writing are different things, and they are meant to look different. Never colour a heading amber to make it look clickable — make it a link or leave it alone.

## Badge

Use a badge for a short label that is not a link: a language, a topic, a state. Never use one as a button; a badge-shaped button is a trap.

Neutral is for anything without its own colour, `badge-accent` is a topic, `badge-state` is progress or status — not emphasis — and `badge-solid` is a count on the raised block. The edge is drawn in the badge's own type colour, so a badge can never become less legible than the word in it.

## Card

Use a card for an item in a grid of peers: a repository in `/projects/`, an entry in a journal grid. A single card is a page with a box drawn round it — if there is one item, write the page instead.

The repository card carries a thumbnail, a title in the display face, a tagline and a line of meta; the entry card carries a kicker, title, dek and a topic badge. Hover changes the title to amber and adds the bloom. Nothing moves.

## Entry list

The entry list is the site's default for a reading list: date, title, dek on one line, grouped by topic on `/journal/`. A list of dates scans faster than a grid of cards, and the site has one author, so it gets one list. The dek is optional — an entry with no description ends at its title.

Nothing in the list is the empty state's job. When there are no entries, use the empty state; do not ship an empty list.

## Nav

The header is on every page: wordmark, four links, one line. It wraps rather than collapsing, so there is no menu button and no script, and Series moves to the footer below 640px rather than making a fifth link fit on a phone.

The current page is amber, and hover is amber, so the marker is colour and never a new weight. Do not add a fifth link without removing one: four is what fits beside the wordmark.

## Hero

Use the hero once, at the top of the home page: one photograph, the wordmark, two sentences, the topic row. Do not use it on an inner page — a photograph that fills the viewport on a page someone came to read pushes the answer below the fold.

The type over the image sits on a scrim and is measured against the brightest pixel behind it. The drift is the site's only motion at that scale, and it stops when the reader asks for reduced motion.

## Prose

Use prose for anything someone reads: an entry, a repository page, About, credits.

Say what you mean with the right block. A **blockquote** is someone else's words. A **callout** is your own caveat or measurement sitting beside the argument. If it is neither of those, it is a paragraph. A **code block with a caption** is a figure whose content is code, and the caption is where the provenance goes. A **table** breaks out of the measure and scrolls sideways rather than squeezing.

Inside a column, `h2` is a mono label and `h3` is one rung below it. Anton starts at the section title, not at a heading inside a column: at 22px in a 544px measure the condensed face reads as a shout.

## Figure

Use a figure for a picture that is evidence, and give it the file's real width and height so the browser can reserve the box. The drawn height always comes from the ratio, which is why a photograph cannot arrive stretched. Add `srcset` with `sizes` when more than one width exists, and put the provenance in the caption.

A figure is capped at 1000px inside prose and outside it, so nothing runs the full 1200px column.

## Empty state

Use the empty state when a collection has nothing in it: a title that names the absence, one line on what happens next, a link out.

Do not ship five empty headings, a spinner, or a zero-count table. Two places use it today: `/journal/` before entries exist and `/projects/` before the repository pages landed.

## Footer

The footer is on every page: the subtitle, then the five ways out — RSS, GitHub, image credits, the design system, and how to say hello. It is 13px mono in dust, and its links are starlight.

## Poster

A poster advertises a library: 2:3, key art on top, type on the void band below. It is the only component measured against its own width rather than the window, so the same poster is a 160px thumbnail in the strip and a 380px one-sheet on `/now-showing/`.

Three variants, and the content chooses: **with a still** when the repository has a figure, **without one** when it does not, and **text only** when there is no art at all. Never put text over the key art — every word sits on the void band, which is what keeps the contrast guarantee true for all twenty campaigns under all three identities. The release number is the one exception and it carries its own film.

The cast credit is the poster's floor. With a member from `_data/cast.yml` it names them; with no member it prints the parts of the film. Do not leave it out when the poster is wide enough to carry it.

## Now showing strip

Use the strip once, on the home page. It advances one poster per beat in CSS and carries the same drawn-box pause control as the crawl, so a moving row can always be stopped. Reduced motion stops it and removes the control.

Do not put a second strip anywhere: `/now-showing/` is the gallery, and it does not move.

## Pagination: not built, and why

There is no pager and no previous/next pair, because the site does not need one yet. `/journal/` renders every entry grouped by topic in one document, and an entry ends with one link back to the journal — entries are grouped by subject rather than ordered as a series, so "next" would be a different subject, not the next step in an argument.

If the journal ever passes a few hundred entries, the cheapest honest change is a `paginate` block on a generated `/journal/page:N/` path that reuses the entry list and the same `text-link` row. Build it then, not now.

## Contrast

Every colour on the site is measured, and a component author needs five of them. The rest of the pairs — the alert, the plum mark, the decal film, the poster plate — belong to one component each and are in `docs/design-system.md`, beside the reasoning for why they exist.

| Job | Token | On the ground |
| --- | --- | --- |
| Body and headings | `--star` | 16.9:1 |
| Secondary type | `--starlight` | 15.4:1 |
| Meta, captions, disabled | `--dust` | 7.5:1 |
| Chrome accent, links outside prose | `--accent-text` | 13.1:1 |
| State and focus rings | `--state` | 12.9:1 |

Text clears 4.5:1 and a control edge 3:1; nothing on the site sits below either. `npm run contrast` prints every pair over all three identities and exits non-zero on a failure, so the numbers here cannot drift from the stylesheets without the build saying so. `/style/` prints the same numbers beside each swatch on the live site.
