# When to use what

The workbench imports `assets/tokens.css` and `assets/notebook.css` directly. There is no Storybook-only stylesheet, so a story and the page it came from cannot disagree: if a component needs a new rule, the rule goes into the site's stylesheet and both places get it.

The site is one dark ground, cream type, and one accent per job. Nothing here is decorative: every colour is a token, every edge is the one hairline or a measured border, and the only radius is `--radius: 0`.

## The rules the palette keeps

| Job | Token | Measured |
| --- | --- | --- |
| Body and headings | `--star` | 16.9:1 on `--void` |
| Secondary type | `--starlight` | 11.4:1 |
| Meta, captions, disabled | `--dust` | 6.6:1 |
| Chrome accent, links outside prose | `--rust-text` | 5.6:1 |
| Prose links only | `--nebula-text` | 6.3:1 |
| State, focus rings | `--teal` (edges) / `--teal-text` (type) | 4.3:1 / 5.9:1 |
| Quotation edge | `--plum-mark` | 4.0:1 |
| Dividers | `--line` | hairline, not a control edge |

`npm run contrast` in `storybook/` prints all 38 pairs the components ship, text at a 4.5:1 floor and control edges at 3:1. Anything below the floor is a failure, not a judgement call. Dividers are printed for the record and carry no minimum, because they group content rather than identify a control.

## Button

**Use it** for an action: submit, toggle, follow. **Do not use it** for navigation between pages, which is a link, or for an action inside a sentence, which is the `btn-text` variant.

- `btn-primary` — the one action on a view. Rust fill, void type at 4.57:1; hover lifts to `--rust-text` at 5.55:1. Two primaries side by side means neither is primary.
- `btn-secondary` — the alternative in a pair, or an action beside a primary. Dust edge (6.6:1), hover edge and type in rust.
- `btn-ghost` — chrome and dense rows, where a filled box is too loud. It has no boundary at rest by design; its starlight type (11.4:1) is the whole affordance, and hover brings a `--surface` fill with a dust edge (5.7:1).
- `btn-text` — an action that reads as a link, inside a sentence or a row of links.
- Sizes: `btn-sm`, default, `btn-lg`. `btn-block` fills its container.
- States: hover, focus-visible (2px `--teal` ring, 4.3:1), active, disabled. Disabled is dust type (6.6:1) inside a dashed dust edge, so it never falls below the text floor — the states are live in the story, not staged with fake classes.

## Link

**Use a link** to go somewhere. Three forms, and the form is the meaning:

- **Chrome link** (`text-link`, rust, underline drawn as a border) — nav rows, footers, "all entries".
- **Prose link** (nebula, inside `.prose` only) — so a link in an article is visibly a different thing from a link in the chrome.
- **Bare link** — the default `a`, when no component owns the line.

Never colour a heading rust to make it look clickable; make it a link or leave it.

## Badge

**Use a badge** for a short label that is not a link: a language, a topic, a state. **Do not use it** as a button: a badge is not interactive, and a badge-shaped button is a trap.

- Neutral (`badge`) — language, kind, anything without its own colour.
- `badge-accent` — a topic, in the rust accent.
- `badge-state` — progress and status, in teal. Not emphasis.
- `badge-solid` — a count or fact on the raised block, no edge.
- The edge is `currentColor`, so a badge can never be less legible than its own type, and every edge clears 3:1 for free.

## Card

**Use a card** for an item in a grid of peer items: a repository in `/projects/`, an entry in a journal grid. **Do not use it** for a single item — a lone card is a page with a box drawn round it.

- **Repository card** — thumbnail (`card-media`, 16:10 crop), `card-title` in the display face, `card-text` tagline, `card-meta` language and stars. The image is decorative (`alt=""`) because the title carries the name; a card without an image simply starts at the title.
- **Entry card** — a kicker (topic · date) instead of a thumbnail, title, dek, and a topic badge in `card-foot`. No live page uses it yet: the journal index and home page use the entry list, which fits a reading list better. It exists for a journal grid.
- The hairline is the top edge. Hover and focus-visible change the title to rust and strengthen the top edge; nothing moves.

## Entry list

**Use the entry list** for a reading list: date, title, dek on one line, grouped by topic on `/journal/`. It is the site's default for entries because a list of dates scans faster than a grid of cards, and the site has one author.

The dek is optional — an entry with no `description` front matter ends at the title. `Empty` in the story is the same list with nothing in it; the block that replaces an empty list is the Empty state component.

## Nav

**Use the header** on every page: wordmark, four links, one line. It wraps instead of collapsing, so there is no menu button and no script. At 420px it is still one line at 12px; at 390px and below the links wrap onto a second line. Measured on the built site, not assumed.

The current page is rust (`aria-current`), and hover is rust, so the marker is colour and never a new weight. Do not add a fifth link without removing one: four is what fits on a phone line with the wordmark.

## Hero

**Use the hero** once, at the top of the home page: one photograph full bleed, the wordmark, two sentences, the topic row. **Do not use it** on inner pages — a photograph that fills the viewport on a page someone came to read pushes the answer below the fold.

The type over the image is measured against the brightest pixel behind it with the type hidden (wordmark 10.4:1, body 15.3:1), not against the image's average. The drift is the site's only motion and stops under `prefers-reduced-motion: reduce`.

## Prose

**Use prose** for anything someone reads: an entry, a repository page, About, credits.

- **h2** is the display face at `--step-4`; **h3** is a 13px mono label — a heading level, not a smaller title.
- **Blockquote** (plum-mark edge, 4.0:1) is a quotation: someone else's words.
- **Callout** (teal edge 3.8:1 on the raised block) is your own caveat or measurement sitting beside the argument. If it is not a warning and not a quotation, it is a callout; if it is neither of those, it is a paragraph.
- **Code block with a caption** is a figure whose content is code — the caption is where the provenance or the command's result goes.
- **Table** breaks out of the measure and scrolls sideways rather than squeezing, so numbers stay readable at 420.
- **hr** is the one hairline weight, for a real change of subject.

## Figure

**Use a figure** for a picture that is evidence. The `width` and `height` attributes are the file's real ones so the browser reserves the box, but the drawn height always comes from the ratio — `width: 100%`, `height: auto` — which is why a photograph cannot arrive stretched. `srcset` with `sizes` when more than one width exists; the caption goes under a hairline in 13px mono.

Inside prose a figure is capped at `min(100%, 1000px)`; outside prose the same cap applies, so nothing runs the full 1200px column.

## Empty state

**Use the empty state** when a collection has nothing in it: a title that names the absence, one line on what happens next, a link out. **Do not** ship five empty headings, a spinner, or a zero-count table.

Two live uses: `/journal/` with no entries yet, and `/projects/` before the repository pages land.

## Footer

**Use the footer** on every page: the subtitle in the row, then the five ways out — RSS, GitHub, image credits, the design system, and how to say hello. 13px mono upper case in dust, links in starlight.

## Pagination: not built, and why

There is no pager and no previous/next pair, because the site does not need one yet:

- `_config.yml` declares no `paginate`, and `/journal/` renders every entry grouped by five topics in one document. With zero published entries there is nothing to page, and a topic-grouped list stops being scannable long before a pager would save the reader anything.
- An entry page ends with one link back to the journal (`entry-foot`), not previous/next: entries are grouped by topic rather than ordered as a series, so "next" would be a different subject, not the next step in an argument.
- A repository page ends the same way, with a link to all repositories.

If the journal ever passes a few hundred entries, the cheapest honest change is a `paginate` block on a generated `/journal/page:N/` path, reusing the entry list and the same `text-link` row — no new visual component. Build it then, not now.
